# AGENTS.md

Рабочие заметки для агентов и людей, которые правят Lythrum. Подробности
устройства и пользовательские возможности — в [README.md](README.md).

## Что это

Тайлинговый WM для X11 на Go + cgo поверх libX11. Плитки экрана запуска —
живые страницы WebKitGTK 6.0, которые рисуются в offscreen-окне и
копируются на экран через `XPutImage`. Внешних Go-зависимостей нет.

## Перед правкой

```bash
gofmt -w .            # всегда перед коммитом
go build ./...
go vet ./...
go test ./...
```

Тесты, которым нужен дисплей, по умолчанию пропускаются:

```bash
Xvfb :97 -screen 0 1280x800x24 &
DISPLAY=:97 LYTHRUM_X11_TEST=1 go test ./internal/x11
```

Проверить оболочку целиком:

```bash
go build -o /tmp/opencode/lythrum ./cmd/lythrum
DISPLAY=:97 /tmp/opencode/lythrum --config /tmp/wall.json --log debug &
DISPLAY=:97 python3 -c 'import socket,json,os;
s=socket.socket(socket.AF_UNIX);s.connect(os.environ["XDG_RUNTIME_DIR"]+"/lythrum.sock");
s.sendall(json.dumps({"command":"start_screen"}).encode());print(s.recv(65536).decode())'
DISPLAY=:97 import -window root /tmp/shot.png
```

## X11 и Wayland

Оболочка говорит только с X11. Внутри Wayland она работает через XWayland и
управляет лишь X11-окнами. Режим хранится в `wm.Session`
(`internal/wm/session.go`), поднимается в `cmd/lythrum` и показывается в
`--info`, в `Describe()` и в виджете настроек. Флаг `--wayland` подтверждает
автоопределение, а не переключает бэкенд.

GDK бэкенд виджетов не форсируется: `LYTHRUM_WEBKIT_X11=1` просит мост
выставить `GDK_BACKEND=x11` только для GTK-потока. Менять это поведение по
умолчанию нельзя — на Wayland поверхности уезжают в сокет композитора, а на
Xv11/Xvfb получается поверхность 1×1.

Собственного Wayland-компоновщика нет; если он понадобится, это отдельный
пакет `internal/wayland` на libwayland-server или wlroots.

## Границы слоёв

- `internal/layout`, `internal/config`, `internal/search`, `internal/media`,
  `internal/imagex` не импортируют `internal/x11`. Всё, что можно проверить
  без X-сервера, проверяется обычным тестом.
- `internal/desk` собирает каталог плиток (`Catalog`): рабочий стол,
  установленные `.desktop`, файлы домашних папок. Обход идёт в горутине
  `deskCache` (`internal/wm/deskcache.go`) — в цикле событий он занимал бы
  сотни миллисекунд.
- `internal/wm/canvas.go` держит смещение рабочего стола. Окна, обои и иконки
  живут в координатах канваса, мониторы — в корневых: любой новый код обязан
  переводить координаты явно (`ToCanvas`, `ToRoot`, `Viewport`), иначе после
  панорамы окно окажется не там.
- `internal/x11` не знает про оболочку: только libX11.
- `internal/webview` не знает про виджеты: только GTK4/WebKit и `lythrum://`.
- `internal/wm` собирает всё вместе и владеет единственным циклом событий.

## Потоки

1. **Цикл событий X** (`internal/wm/events.go`) — единственный, кто трогает
   клиентов, окна и раскладку.
2. **Поток GTK** — живёт внутри WebKit. Страницы получают команды только
   через idle-колбэки (`lv_post` в `internal/webview/bridge.c`), а ответы
   уходят через `View.Dispatch`, `View.Eval`.
3. **Горутины WM** — ffmpeg, обход файлов, превью (`mediaJobs`,
   `previewQueue`). Всё, что дольше кадра, не должно идти в цикл событий.

Настройки из виджета идут через `WM.queueConfig`: страница получает ответ
сразу, но `w.cfg`, перехват клавиш и раскладку меняет только цикл событий
(`applyPendingConfig`). Раньше виджет дёргал `applyConfig` сам, и детектор
гонок ловил это сразу. Читать настройки из других потоков можно только
через `w.config()`.

Нарушение этого правила уже стоило зависания интерфейса: `media.list`
вызывал `ffprobe` на каждом файле и блокировал цикл на минуты.

## Правила для C-моста

`internal/webview/bridge.c` — единственное место, где живёт GTK.

- **Владение объектами.** Проверяй `transfer-ownership` в GIR, а не по
  памяти. `webkit_uri_scheme_request_get_http_headers()` отдаёт *заимствованный*
  ref: `soup_message_headers_unref()` там был двойным освобождением и
  ломал память процесса (`g_atomic_rc_box_release_full`, `malloc(): unaligned
  tcache chunk detected`).
- **Поток ответа.** `g_memory_input_stream_new_from_data()` отдаёт тело
  наружу: снимать свой ref нельзя, WebKit читает поток после возврата.
- **Ошибки X.** Ошибки протокола читаются из общей слот- переменной
  `ly_error_slot` (`ly_collect_errors` в `event.go`), а не своим обработчиком:
  под окнами менеджера сидит много чужих клиентов, и постоянный обработчик в
  `paint.go` записывал в загрузку картинки ошибку, которую вызвал кто-то
  другой. Перед чтением слота проверяй `slot.request == X_PutImage`, иначе
  прилетит ошибка запроса, который ушёл раньше.
- **`XCreateWindow` читает структуру, а не массив.** Аргумент — указатель на
  `XSetWindowAttributes`, и Xlib берёт поля по именам, сверяясь с маской. Массив
  `ulong` читается как `background_pixmap, background_pixel, border_pixmap, ...`,
  из-за чего `event_mask` попадал на место курсора: окна оболочки не получали
  событий, а `override_redirect` брался из чужого поля. Заполняй поля через
  `ly_window_attrs` (`internal/x11/window.go`), никаких массивов.
- **Resize родителя размапливает детей.** Xvfb (и часть серверов) unmaps детей
  окна, которое перерисовали. После `ResizeWindow(frame, …)` окно клиента надо
  мапить заново — иначе приложение выглядит исчезнувшим в момент тайлинга.
- **Не форсировать `GDK_BACKEND`.** При `GDK_BACKEND=x11` поверхности GTK4
  приходили размером 1×1 и снимки падали с «There was an error creating the
  snapshot».
- **Локаль важна.** GLib сам вызывает `setlocale(LC_ALL, "")` внутри
  `gtk_init`. Если в системе не сгенерирован `en_US.UTF-8`, GTK ругается
  «Locale not supported by C library» и работает в C-локали. `lv_gtk_thread`
  подставляет `C.UTF-8`/`C.utf8` и через переменные окружения, иначе текст
  страниц идёт в неправильной кодировке.

## Ограничения offscreen-рендера

- В невидимом окне нет ни фокуса, ни каретки. `common.js` запоминает
  элемент под последним кликом (`focused`), а `__lythrumKey` правит его
  значение сам. Поэтому подписи полей обязаны быть связаны с полями
  (`for`/`id`), иначе клик по тексту не доедет до ввода.

- CSS-анимации и переходы не тикают в невидимом окне. Страница помечается
  `html.offscreen` (`internal/widget/assets/common.css`), и всё, что relies
  на `transition`, там отключено. Если добавляешь анимацию — сначала
  спроси, поедет ли она в плитке.
- Ширина текста в X11-мосте (`internal/x11/text.go`) меряется в UTF-8
  символах, а не в байтах: обратно русские подписи выглядят вдвое шире и
  обрезаются.
- Шрифт `sans:size=13` не содержит стрелок и прочих пиктограмм — рисуйте
  словами или примитивами X11.

## Стиль

- Комментарии объясняют «почему», а не «что»; на английском.
- Имена ошибок — `ErrSomething`, тексты ошибок начинаются с `пакета:`.
- Внутренние команды оболочки (`runAction`, IPC, виджеты) делят один
  строковый формат: `"действие аргументы"`.
- Публичные функции пакета документированы; приватные — когда причина
  неочевидна.
- Никаких новых внешних модулей без обсуждения.

## Проверка изменений

| область      | что сделать                                                  |
|--------------|--------------------------------------------------------------|
| геометрия    | тест в `internal/layout`, без X                               |
| конфиг       | тест на `Merge`: неверный патч отклоняется целиком и ничего не меняет |
| виджет       | тест в `internal/widget` на JSON-форму ответа; вживую — клик по плитке |
| иконки стола | `go test ./internal/layout` на геометрию, вживую — двойной клик по значку |
| канвас       | `go test ./internal/wm` на смещение, вживую — тащить пустое место мышью |
| оболочка     | `go test ./internal/wm`, вживую — скриншот с Xvfb            |
| C-мост       | вживую: `grep -c GLib-CRITICAL лог` должно быть 0            |
| текст/шрифты | `LYTHRUM_X11_TEST=1 go test ./internal/x11`                   |

Живая проверка считается пройденной, если: плитки отрисованы, клик по плитке
открывает виджет на весь экран, ввод доходит до страницы, `Применить`
меняет оболочку без перезапуска, а в логе нет `GLib-CRITICAL`, `malloc`
и повторяющихся `cannot paint`. Окно, запущенное с плитки (`xdemo -n 3` для
быстрой проверки), должно быть видно и затайлено: клиент мапится самим
менеджером, и рамка без `override_redirect` уводит его в собственный тайлинг.

## Известные долги

- **Свойства X11 в формате 32 байт пишутся не полностью.**
  `TestPropertyRoundTrip` и `TestPropertyMatchesExternalReader`
  (`internal/x11/properties_test.go`) падают при `LYTHRUM_X11_TEST=1`, причём
  падают и на чистом Xvfb без оболочки, то есть дело не в окружении.
  Воспроизведение: записать `[]uint32{0x0A0A0A0A × 8}` через
  `SetCardinals` и прочитать `GetProperty`: возвращается
  `0a0a0a0a 00000000 0a0a0a0a 00000000 ...`, а внешний `xprop` видит
  `168430090 × 4` и дальше мусор. Значит на сервер уходит только половина
  данных, а формат 8 при этом работает. Подозрение на `ly_set_property`
  в `internal/x11/prop.go`: проверить, сколько байт Xlib реально прикладывает
  к `ChangeProperty`, и не мешает ли сюда `XInitThreads` (его надо вызывать
  до первого `XOpenDisplay`). Пока баг не исправлен, не полагаться на
  чтение обратно `CARDINAL[]` свойств длиннее 16 байт.

- Системные сочетания (Ctrl+C и подобные) в полноэкранном виджете не
  работают: страница получает только синтетические события.
- Виджет, открытый на весь экран, забирает клавиатуру целиком: пока он
  открыт, сочетания оболочки не срабатывают.
- `NewVisibleView` (`internal/webview/webview.go`) — нерабочий путь, давал
  чёрный экран; нигде не используется, кандидат на удаление.
- `GInputStream` в `lv_on_reply` намеренно не освобождается — небольшая
  утечка на каждый ответ схемы в обмен на целые изображения.
- Deprecated GTK4 API в `lv_make_override` и `lv_hide`.
- Превью в плитках грузятся полноразмерными файлами, а не миниатюрами.
- Аудио и видео внутри виджетов проверены только частично: в домашней
  папке не было треков.
